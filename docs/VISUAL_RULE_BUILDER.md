# 可视化规则构建器使用说明

## 功能概述

可视化规则构建器提供了一个图形化界面，让运维人员无需手写代码即可构建Drools规则。通过简单的点击、选择和输入操作，即可完成规则的创建。

## 主要组件

### 1. RuleConditionBuilder - 条件构建器

用于构建规则的 `when` 部分，支持：

#### 功能特性
- ✅ 可视化添加/删除条件
- ✅ 选择类（Person, Order, Product等）
- ✅ 选择字段（从类的字段列表中选择）
- ✅ 选择操作符（==, !=, >, <, >=, <=, contains, matches等）
- ✅ 输入比较值
- ✅ 支持AND/OR逻辑组合
- ✅ 自动生成DRL代码

#### 操作符说明
| 操作符 | 说明 | 示例 |
|--------|------|------|
| == | 等于 | age == 18 |
| != | 不等于 | status != "CLOSED" |
| > | 大于 | amount > 1000 |
| < | 小于 | stock < 10 |
| >= | 大于等于 | age >= 18 |
| <= | 小于等于 | price <= 999 |
| contains | 包含 | name contains "张" |
| matches | 正则匹配 | email matches ".*@example.com" |
| memberOf | 在集合中 | category memberOf $validCategories |

#### 使用示例

**场景：检查成年人**
1. 点击"添加条件"
2. 变量名：`p`
3. 类：选择 `Person`
4. 字段：选择 `age`
5. 操作符：选择 `>=`
6. 值：输入 `18`

**生成的代码：**
```drl
$p: Person(age >= 18)
```

**场景：多条件组合**
1. 第一个条件：`$p: Person(age >= 18)`
2. 点击"添加条件"
3. 选择逻辑操作符：`AND`
4. 第二个条件：`$p2: Person(sex == "male")`

**生成的代码：**
```drl
    $p: Person(age >= 18)
    and $p2: Person(sex == "male")
```

### 2. RuleActionBuilder - 动作构建器

用于构建规则的 `then` 部分，支持：

#### 动作类型

##### 📞 调用方法
- 调用对象的实例方法
- 示例：`$p.setAdult(true)`

##### 🔄 更新对象 (update)
- 通知引擎对象已修改
- 示例：`update($p)`

##### ➕ 插入对象 (insert)
- 向工作内存插入新对象
- 示例：`insert($newOrder)`

##### ❌ 删除对象 (retract)
- 从工作内存删除对象
- 示例：`retract($oldRecord)`

##### ✏️ 修改对象 (modify)
- 原子性修改对象
- 示例：`modify($p) { setAge(19) }`

##### ⚡ 调用函数
- 调用静态方法或工具类
- 示例：`DateUtils.format(date, "yyyy-MM-dd")`

#### 使用示例

**场景：设置成年标志并更新**
1. 动作类型：选择"调用方法"
2. 对象：输入 `$p`
3. 方法：选择 `setAdult`
4. 参数：输入 `true`
5. 点击"添加动作"
6. 动作类型：选择"更新对象"
7. 对象：输入 `$p`

**生成的代码：**
```drl
    $p.setAdult(true);
    update($p);
```

**场景：调用工具类**
1. 动作类型：选择"调用函数"
2. 对象：选择 `DateUtils`
3. 方法：选择 `format`
4. 参数1：输入 `$date`
5. 参数2：输入 `yyyy-MM-dd`

**生成的代码：**
```drl
    DateUtils.format($date, "yyyy-MM-dd");
```

## 使用流程

### 步骤1：创建规则
1. 在规则列表中点击"添加规则"
2. 输入规则名称

### 步骤2：选择编辑模式
在规则表单中，找到"编辑模式"开关：
- 开启：使用可视化构建器
- 关闭：使用代码编辑器

### 步骤3：构建条件（When）
1. 点击"添加条件"按钮
2. 填写：
   - 变量名（如：`p`, `order`, `product`）
   - 类名（从下拉列表选择）
   - 字段名（根据类自动显示可用字段）
   - 操作符
   - 值
3. 需要多个条件时：
   - 点击"添加条件"
   - 选择AND或OR逻辑
   - 配置新条件

### 步骤4：构建动作（Then）
1. 点击"添加动作"按钮
2. 选择动作类型
3. 根据动作类型填写相应参数
4. 可添加多个动作（按顺序执行）

### 步骤5：查看生成的代码
- 点击"查看生成的代码"展开预览
- 代码实时更新
- 可切换到代码模式手动编辑

## 完整示例

### 示例1：成年人规则

**规则描述：**如果一个人年龄大于等于18岁，设置其为成年人并更新。

**可视化配置：**

**条件（When）：**
- 变量名：`p`
- 类：`Person`
- 字段：`age`
- 操作符：`>=`
- 值：`18`

**动作（Then）：**
1. 动作类型：调用方法
   - 对象：`$p`
   - 方法：`setAdult`
   - 参数：`true`

2. 动作类型：更新对象
   - 对象：`$p`

**生成的完整规则：**
```drl
rule "CheckAdult"
    salience 10
when
    $p: Person(age >= 18)
then
    $p.setAdult(true);
    update($p);
end
```

### 示例2：订单折扣规则

**规则描述：**如果订单金额大于1000且状态为待处理，应用折扣。

**可视化配置：**

**条件（When）：**
1. 变量名：`order`
   - 类：`Order`
   - 字段：`amount`
   - 操作符：`>`
   - 值：`1000`

2. 逻辑：`AND`
   - 变量名：`order2`
   - 类：`Order`
   - 字段：`status`
   - 操作符：`==`
   - 值：`PENDING`

**动作（Then）：**
1. 动作类型：调用方法
   - 对象：`$order`
   - 方法：`calculateDiscount`
   - 参数：`0.1`

2. 动作类型：更新对象
   - 对象：`$order`

**生成的完整规则：**
```drl
rule "OrderDiscount"
    salience 10
when
    $order: Order(amount > 1000)
    and $order2: Order(status == "PENDING")
then
    $order.calculateDiscount(0.1);
    update($order);
end
```

## 优势对比

### 传统代码模式
❌ 需要了解DRL语法
❌ 容易出现语法错误
❌ 需要记忆类名和方法名
❌ 调试困难

### 可视化模式
✅ 无需学习语法
✅ 下拉选择，不会出错
✅ 自动提示可用的类和方法
✅ 实时预览生成的代码
✅ 适合运维人员操作

## 注意事项

1. **类定义文件**
   - 确保 `public/mock/class.json` 包含所有需要的类定义
   - 添加新类时需要更新该文件

2. **变量命名**
   - 变量名应有意义（如：`p`, `order`, `product`）
   - 同一规则内变量名不要重复

3. **参数类型**
   - 字符串参数会自动加引号
   - 数字和布尔值不加引号
   - 变量引用（以$开头）不加引号

4. **模式切换**
   - 从可视化切换到代码模式：保留生成的代码
   - 从代码切换到可视化模式：重置为空，重新构建

5. **代码预览**
   - 每次修改都会实时更新生成的代码
   - 可以随时查看生成结果

## 扩展功能

如需添加新的类或方法：

1. 编辑 `public/mock/class.json`
2. 添加类定义和方法信息
3. 重新加载页面

示例：
```json
{
  "classes": [
    {
      "name": "YourClass",
      "fullPath": "com.example.model.YourClass",
      "package": "com.example.model",
      "description": "您的类描述",
      "methods": [...],
      "fields": [...]
    }
  ]
}
```

## 技术支持

如遇问题，请检查：
1. 浏览器控制台是否有错误
2. 类定义文件是否正确加载
3. 生成的代码是否符合DRL语法
